# Planning — 작업 계획 수립 가이드

사용자 요청을 실행 가능한 단계별 계획으로 분해하는 절차 가이드.

## 계획 수립 절차

### 1. 요청 분석

사용자 요청에서 다음을 파악한다:
- **목표**: 무엇을 달성하려는가
- **범위**: 어떤 모듈이 영향받는가 (api / batch / web / modules / supports)
- **유형**: 새 기능 / 기존 변경 / 버그 수정 / 리팩토링

### 2. 영향 범위 식별

```
apps/api     → 백엔드 API 변경 → implementer + db-migrator
apps/batch   → 배치 변경 → implementer (batch-job 스킬)
apps/web     → 프론트엔드 변경 → frontend-dev
modules/*    → 공통 모듈 변경 → implementer
supports/*   → 지원 모듈 변경 → implementer
```

영향 범위에 따라 필요한 에이전트를 결정한다.

### 3. 작업 분해

작업을 "하나의 에이전트가 한 번에 수행 가능한 크기"로 분해한다.

**분해 기준:**
- 레이어별 분리: domain → infrastructure → application → interfaces
- 모듈별 분리: api / batch / web
- 의존성 방향: 하위 레이어부터 상위 레이어 순서

**담당 에이전트 할당:**

| 작업 유형 | 에이전트 |
|-----------|---------|
| 코드 구조/영향도 분석 | analyzer |
| 백엔드 API 구현 | implementer (api-feature 스킬) |
| 배치 Job 구현 | implementer (batch-job 스킬) |
| DB 마이그레이션 | db-migrator |
| 프론트엔드 구현 | frontend-dev |
| 규칙 기반 검증 | qa-validator |
| 심층 코드 리뷰 | code-reviewer |
| 문서 갱신 | tech-writer |

### 4. 의존성 그래프

```
[planner] → [analyzer] → [implementer] ─┬→ [db-migrator] (DB 변경 시)
                                         └→ [frontend-dev] (프론트 변경 시)
                                              ↓
                                         [qa-validator] → [code-reviewer]
                                              ↓ (수정 루프)
                                         [tech-writer]
```

### 5. 리스크 평가

각 작업에 대해:
- **기존 코드 영향**: 어떤 기존 기능이 깨질 수 있는가
- **DB 변경 위험**: 데이터 손실 가능성, 롤백 전략
- **성능 영향**: 새 쿼리, 캐시 변경 영향
- **보안 영향**: 인증/인가 변경, 입력 검증

## 계획서 형식

```markdown
# 작업 계획: [제목]
> 생성일: [날짜]

## 목표
[한 문장으로 달성하려는 것]

## 영향 범위
| 모듈 | 영향 | 에이전트 |
|------|------|---------|

## DB 변경
[있음/없음] — [있으면 간략 설명]

## 작업 단계

### Step 1: [제목]
- **담당**: [에이전트]
- **내용**: [설명]
- **산출물**: [파일/결과]
- **의존**: [없음 / Step N]

### Step 2: ...

## 리스크
| 리스크 | 영향도 | 대응 |
|--------|--------|------|

## 예상 변경 파일
- [path] — [요약]
```

## 규모별 계획 수준

| 규모 | 기준 | 계획 수준 |
|------|------|----------|
| 소 | 1-2파일, 단일 레이어 | 계획 생략 가능 (analyzer만 실행) |
| 중 | 3-10파일, 2-3 레이어 | 간략 계획 (Step 3-5개) |
| 대 | 10+파일, 전 레이어 또는 다중 모듈 | 상세 계획 (Step 5-10개) + `.ai/planning/`에 보존 |
