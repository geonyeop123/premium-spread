# #140 실계정 알림 자산 표기 정합 — 설계

source: https://github.com/geonyeop123/premium-spread/issues/140 · 상위 #137 · 선행 #138(레버리지 조회, 머지됨)

## 문제

수익·정시 알림의 바이낸스 블록 `평가액`은 `현재가 × 수량`(레버리지가 걸린 명목 규모)이다. `자산` 칸의 `총 자산`은
`빗썸 평가액 + 빗썸 원화 잔고 + 바이낸스 marginBalance × 환율`이라, 블록 평가액을 더해도 총 자산과 맞지 않는다.
총 자산 계산은 맞으므로 **표기만** 바꾼다. 순손익·김프 계산은 건드리지 않는다.

## 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | 바이낸스 블록 `평가액` = `AccountAssetBreakdown.marginBalanceKrw (marginBalanceUsdt)`. 표기는 `14,000,700원 (10,000.50 USDT)`로 자산 칸의 `바이낸스 증거금+손익`과 같은 문자열이다 | 이슈 범위 1. 총 자산에 이미 들어가는 값과 같은 값을 써야 합이 정확히 맞는다(같은 BigDecimal, 같은 반올림) |
| D2 | 잔고 조회 실패(`balance == null`)면 블록 `평가액`은 `없음`, 수동 모드(`MANUAL_ENV`)면 `수동 모드 — 표시 안 함` | 자산 칸(#105 §5.3)과 같은 규칙. 수동 모드는 "지금처럼 숨긴다"(이슈 범위) |
| D3 | 블록에 `포지션 규모 {명목 USDT} ({n}x)` 줄을 `평가액` 바로 뒤에 추가한다. 명목 = 바이낸스 청산가(매도호가 VWAP) × 수량 — 기존 평가액 값 그대로다. USDT 만 쓴다 | 이슈 예시 형식. 원화 명목은 자산과 혼동되므로 싣지 않는다 |
| D4 | 레버리지 = `pnl.position.foreign.symbolConfig?.leverage`(#138). null(조회 실패·수동 모드)이면 `포지션 규모 29,579.20 USDT`처럼 배수 없이 쓴다 | 이슈 범위 2. 청산 근접 알림의 `확인 불가` 표기와 달리, 이 줄은 명목이 주 정보이므로 배수만 생략한다 |
| D5 | `ForeignLegBreakdown`의 `valueUsdt`·`valueKrw`를 `notionalUsdt` 하나로 바꾸고 `leverage: Int?`를 더한다. 평가액(증거금) 값은 기존 `assets`에서 읽는다 | 원화 명목은 더 이상 표시하지 않는다. 같은 값을 두 곳에 두지 않는다 |
| D6 | 문구 정본 `docs/work/alert-message-template/message-spec.md`(수익·정시 두 절)와 `docs/runbooks/account-pnl-alert.md` 예시·모드표·체크리스트를 같은 커밋 범위에서 갱신한다 | 이슈 범위 "문구 정본" |
| D7 | 자산 칸에서 `바이낸스 증거금+손익` 행을 지운다. 메일 `■ 자산`은 `총 자산`·`잔여 금액`·`USDT 원화가`, Discord 자산 첫 행은 `총 자산` 1칸이 된다 | 블록 평가액과 같은 값의 중복 제거 — 계약 승인(2026-11-13) 사용자 결정 |

## 영향 범위

- `domain` 모듈만: `AccountPnlBreakdown.kt`, `AccountPnlAlertContent.kt`와 각 테스트
- 문서 2개. 저장·스키마·외부 API·라우팅 변경 없음

## 검산

픽스처(빗썸 평가액 42,161,000 · 빗썸 원화 1,234,567 · margin 10,000.50 USDT × 1,400 = 14,000,700)에서
`42,161,000 + 1,234,567 + 14,000,700 = 57,396,267 = 총 자산`. 세 값은 각자 원 단위로 반올림해 표시하므로 일반 입력에서는
최대 ±1원(반올림 3회) 차이가 날 수 있다 — 이슈의 "표시 반올림 차이 제외".
