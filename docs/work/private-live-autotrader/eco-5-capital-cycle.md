## 1. 전략 계약 (이 산출의 전제)

| 항목 | 값 |
|---|---|
| 진입 | 목표 프리미엄에서 빗썸 현물 매수 + 바이낸스 USDT-M perp 매도 |
| 청산 | 진입 프리미엄 + 1.0%p 도달 |
| 재진입 | 프리미엄이 직전 진입 수준으로 복귀 시 |
| 사이징 | 매 사이클 양쪽 잔고로 물량·레버리지 재계산. 양쪽 100% 투입 |
| 증거금 버퍼 | 없음 (바이낸스 잔고 전액을 증거금으로) |
| **정지 캡 ①** | **바이낸스 레버리지 7배 도달** |
| **정지 캡 ②** | 투입액이 총자산의 60% 미만 (자본 효율 바닥) |

## 2. 핵심 관계식

### 레버리지는 독립 변수가 아니라 잔고 비율이다

양쪽을 100% 투입하는 물량이 일치해야 하므로:

```
빗썸    Q = B_k / K
바이낸스 Q = B_b · L / F          (K = F · X · (1+P))

  →   L  =  R / (1+P)        where  R = B_k / (X · B_b)
```

`B_k` 빗썸 원화 잔고 · `B_b` 바이낸스 USD 잔고 · `X` 환율 · `P` 진입 프리미엄.

**레버리지는 두 계정 잔고 비율의 함수다.** 절대 가격에 무관하다 — 사이클 간 상태 전이를 `R` 하나로 추적할 수 있다.

### 사이클 순손익

```
순익 = Q · X · (F₁·P₁ − F₀·P₀)
```

`F` 해외가 · `P` 프리미엄 · 아래 첨자 0은 진입, 1은 청산. 해외가가 보합이면 `명목 × 갭`으로 수렴한다.

**같은 1%p 갭이라도 명목이 큰 쪽에 붙는다.** 보유 중 BTC가 오르면 회당 수익이 크고, 내리면 작다.

### 정지 캡을 빗썸 비중으로 환산

```
투입액/총자산 = B_k / (B_k + X·B_b)      (레버가 캡 미달일 때 빗썸이 물량을 제한)

효율 캡 60%   → 빗썸 비중 60.0%   (하단 — 바이낸스 과잉)
레버 캡 7배   → 빗썸 비중 87.7%   (상단 — 바이낸스 고갈)
```

**두 캡은 하나의 코리도다.** 자본은 60%~87.7% 사이에 있어야 하고, 사이클이 그 값을 밀어낸다.

## 3. 마름의 원인

프리미엄 수익이 아니다. **보유 구간의 BTC 가격 방향**이다.

| 보유 중 실제 움직임 | 빗썸 | 바이낸스 | 비율 `R` |
|---|---|---|---|
| 해외가 보합, 한국가 상승 | 갭 전액 | 변화 없음 | 완만 상승 |
| 한국가 보합, **해외가 하락** | 0 | **레버 배수로 증가** | 하락 → 효율 캡 방향 |
| 둘 다 상승, 한국이 더 | 크게 + | 레버 배수로 감소 | 급상승 → 레버 캡 방향 |

바이낸스 잔고는 BTC 변동의 **레버 배수**로 반응한다. 4.8배에서 BTC +3%는 잔고 −14.5%다.

사이클 사이에는 포지션이 없으므로 그 구간의 가격 변동은 무관하다. **보유 구간만 계산에 들어간다.**

프리미엄만 움직이고 BTC가 보합인 경우에도 정지한다 — 수익 전액이 빗썸에 쌓여 비중을 상단으로 밀기 때문이다. **수익 자체가 코리도를 밀어낸다.**

## 4. 실측 입력

Binance `GET /fapi/v1/fundingRate` (BTCUSDT, 공개), 표본 500건 · 2026-03-12 ~ 08-26 (166일).

| 항목 | 값 |
|---|---|
| markPrice | $70,286 → $78,505 (+11.7%) |
| 8h 펀딩률 | 평균 **+0.00251%** · 중앙 +0.00298% · 표준편차 0.00480% |
| 펀딩 양수 비율 | 72.4% (숏 수취 구간) |
| 연 환산 | +2.75% |
| 3일 창 최대 상승 | **+21.0%** (창 491개) |
| 7일 창 최대 상승 | **+24.3%** (창 479개) |

**펀딩은 마름을 상쇄하지 못한다.** 명목 기준 0.0075%/일 → 잔고 기준 약 0.036%/일. 3일 보유에 0.11%다. 같은 기간 3% 가격 변동이 잔고의 14.5%를 먹는 것과 비교하면 약 1/100이다.

가정값: 바이낸스 taker 편도 0.04% · 유지증거금률 0.4% · 환율 1,400 고정 · 빗썸 수수료 0% (API 거래 무료). **빗썸 수수료를 0.25%로 바꿔도 사이클 수 중앙값이 바뀌지 않는다** — 정지를 결정하는 것은 비율 드리프트이고 왕복 0.5%는 그 옆에서 잡음이다.

사이클 간 환전 스프레드는 0으로 둔다. 자본이 사전 배치돼 있고 사이클 사이 환전이 없다. `ECO-1`이 요구하는 재배치 환전·이체 비용은 정지 이후 비용이며 항목 3에서 다룬다.

### 목적함수에 따라 최적 배분이 다르다

| 목적 | 최적 빗썸 비중 |
|---|---|
| 사이클 수 최대 | 69~71% |
| 재배치 전 누적수익 최대 | 73% (2.79M — 83%의 **2.0배**) |
| **시간당 수익 최대** | **81%** |
| 회당 수익 최대 | 높을수록 |

시간당 수익 곡선은 77~83% 구간에서 평평하다(차이 1.5% 이내). **수익 관점에서 현행 83%는 거의 최적이다.** 배분을 낮춰 얻는 것은 수익이 아니라 꼬리 위험 감소다 — 7일 보유에서 83%는 3.3% 확률로 청산되고 79%는 0이다.

## 6. 산출 — 항목 2

```
                 ┌── 효율 캡 60% ────────── 레버 캡 7배 87.7% ──┐
빗썸 비중         60% ├──────────────────────────────────┤ 87.7%
                      ↑            ↑
                   79% 권고     83% 현행
```

경로는 두 방향이다.

- **BTC 상승 우세** → 바이낸스가 레버 배수로 마름 → `R` 상승 → 상단(레버 캡) 이탈. 실측 정지 사유의 다수
- **BTC 하락 우세** → 바이낸스가 불어남 → 빗썸 비중 하락 → 하단(효율 캡) 이탈. 빗썸 원화가 헤지 상대를 못 찾아 유휴화

자본이 0이 되는 경로는 아니다. **비율이 코리도를 벗어나 거래가 멈추는 것**이며, 해소는 수동 재배치다.

청산은 별개 경로다. 보유 중 BTC가 청산 거리를 넘으면 캡 검사 이전에 강제 종료된다. 캡은 진입 시점 검사이므로 보유 중에는 아무것도 막지 않는다 — `SAFE-7`이 요구하는 liquidation headroom·stress 기준이 이 공백을 메워야 한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 레버 캡 | **7배** | owner 경험. 6배는 코리도 상단이 85.9%로 좁았다 |
| 초기 배분 | **빗썸 79~81%** | 시간당 수익 최적점이며 청산 확률이 3.3% → 0.8~0% |
| 총자산 2,890만 기준 | 빗썸 2,280만~2,340만 / 바이낸스 $3,920~$4,330 | 현행 대비 $420~830 이전 |

현행 2,400만 / $3,500에서 **$400~800을 바이낸스로 옮기는 변경**이다. 시간당 수익은 유지하면서 7일 보유 청산 위험을 없앤다.

## 8. 미산출과 한계

### `ECO-5` 항목 3·4

- **재배치 lead time** — 빗썸 출금 → 전송 → 바이낸스 입금의 실제 비용·소요 시간. 실계정 필요. `ACT-2` 이전에 측정한다
- **재배치 실패 시 거동** — 출금 지연·한도·거래소 점검 시 동작. 설계 결정이며 Phase 3 `P3-O16`(`SAFE-9` 기반 신규 진입 차단)이 구현한다

### 이 산출이 답하지 못하는 것

- **사이클 하나가 달력으로 며칠인가.** 보유 시간은 모델 입력이지만, 청산 후 프리미엄이 진입 수준으로 복귀할 때까지의 대기 시간은 데이터가 없다. "중앙 9 사이클마다 재배치"는 성립하지만 그것이 2주인지 2개월인지 말할 수 없다. 원/일 값은 `T=14일` 가정이며 배분 간 **상대 비교**만 유효하다
- **1%p 갭이 열리는 빈도.** 진입 기회 자체의 빈도. 같은 이유로 미상

두 값 모두 `P1-O1` 최소 수집 계약이 채운다. 이 산출의 가장 큰 공백이며, 장기 evidence clock이 아직 시작되지 않았다는 사실(§4.4)과 같은 원인이다.

### 방법상 한계

- **표본이 166일 한 구간이다.** 이 기간 BTC가 +11.7%였다. 급락장·장기 횡보장에서 결과가 달라진다
- **가격창을 순환 재사용한다.** 런이 길어지면 같은 시계열을 다시 쓰므로 큰 변동을 만날 확률이 올라간다. 낮은 배분(69~71%)의 청산 건수가 높게 나오는 것은 이 아티팩트이며 실제 효과가 아니다. **청산 건수는 83% vs 79%의 방향성만 신뢰하고 절대값은 쓰지 않는다**
- **보유 중 BTC 변동을 창 하나로 대표한다.** 진입·청산 시점의 실제 프리미엄 경로가 아니라 보유 기간 가격 변화만 쓴다. 프리미엄 시계열이 쌓이면 진입·청산 시점을 실제 규칙으로 판정해 교체한다
- **환율을 고정했다.** 실제로는 환율 변동이 프리미엄과 손익 배분에 함께 들어간다
- **`leverageBracket`을 확인하지 않았다.** 명목 약 $17,000 구간에서 7배는 제약이 아닐 것으로 보지만 실계정 조회로 확인해야 한다

## 9. 재현

산출 스크립트는 이 저장소에 커밋하지 않았다. 입력이 외부 API 응답 한 번(`GET /fapi/v1/fundingRate?symbol=BTCUSDT&limit=1000`)과 위 §1·§4의 파라미터뿐이므로, §2의 관계식과 §4의 값으로 재현할 수 있다. Phase 1에서 경제 엔진(`ECO-1`)이 구현되면 이 계산은 엔진 위에서 재수행하며 이 문서는 그 시점의 baseline으로 남는다.
